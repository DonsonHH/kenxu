# 1.4.1 节点状态范围复核

复核起点：本地工作区干净，GitHub main 与本地均为 `07ef4ed`，线上用户端和私有管理端为 1.4.0。GitHub 仓库没有 Actions 工作流或提交检查，不能把没有 CI 失败等同于 CI 通过。

## 已复现并修正

| Before | After | Why |
| --- | --- | --- |
| `src/app.mjs` 的状态接口只筛选节点授权；未完成个人接入或停用的受管节点仍可进入正常数量和图表 | 状态接口与 `/api/me` 共用可领取节点范围，私有管理端仍查看全部源节点 | 防止“2 / 1”等不一致，也不向用户展示尚不可领取的受管入口 |
| `public/app.js` 在登录时保存节点列表，授权变更后只刷新检测与用量 | 在既有查询周期同步当前个人资料和节点范围；跨请求交错时再按当前节点集合筛选检测结果 | 撤销和恢复权限无需重新登录；撤销全部线路时隐藏领取区域 |

后端回归命令 `node --test --test-name-pattern='user health covers only' test/health.test.mjs` 在修正前失败：状态接口多出一个未完成个人接入的节点。修正后覆盖接入、停用、撤销、未授权节点以及管理端全量查看。

浏览器回归在保持登录状态时撤销全部线路，修正前无法从 `0 / 1` 更新为 `0 / 0`，修正后还会隐藏订阅领取区域；恢复授权时自动恢复节点数量与领取入口。测试使用临时数据库和虚构账号，不修改生产账号。

## 动效与界面 review

按 review-animations 与 Emil 界面审查检查，当前实现不增加持续背景运动。指针导航采用 160ms transform／opacity，键盘导航即时切换，减少动态效果不包含位置变化，触摸不触发悬停位移。轮询只更新数据，不播放面板入场动画。本轮修正没有增加新的动效、依赖或探测请求。

动效结论：**Approve**。阻断、高风险和一般动效问题均无待修项。用户端与管理端 1280、1920、2560、3840 CSS 视口以及 390px 手机布局的回归覆盖居中、宽度利用和无横向溢出；不将这些测试等同于所有实体手机、浏览器引擎或无障碍能力的认证。

## 验证与发布边界

本轮复核登录来源与 CSRF、认证限流、账号与配置隔离、个人分流规则、订阅响应头、流量去重、检测新旧口径、界面与动效和 GitHub 同步。HTTP 响应仍是 Jetson 经源节点的 HTTP 首字节时间减去连接准备，不是 ICMP／访问者本机延迟，也不代表线路物理提速。

本机 37 项后端测试、五套隔离 Edge 浏览器流程和生产依赖审计通过。刷新复现中未变化列表移除节点数为零；当前隔离测试平均刷新约 43ms、变化图表更新约 2.6ms。新增资料同步仅复用原查询周期，单次测量不作为跨设备性能承诺。

没有重设账号密码、修改真实授权或个人规则、改写节点凭据、重置历史用量。更新采用新发布目录、停写备份和原子切换，保留上一版本；发布和完整验证结果在确认后记录，不把仅重启服务当作断电重启验证。

## 线上确认

Jetson Node 22 的 37 项后端测试通过，用户与私有管理健康端点均返回 1.4.1。九个关键源文件／构建文件的 SHA256 与本机一致，公开 `client.js` 内容也与本机构建一致。门户、检测器、采集器、中转和 Tunnel 五项服务均 active，原有 enabled 设置未改动；本轮没有执行断电重启。

与本轮停写备份比较，账号表、配置与设置、个人规则、受管凭据与授权、既有用量事件和订阅签名均一致。SQLite 完整性为 ok，外键违规为零。针对原始私有配置中八个长凭据值的跟踪文件扫描无匹配，私有数据和机器 SSH 配置不在 Git 跟踪范围。

代码 review 剩余阻断项为零，但**线路运行状态并非全部正常**：七条源线路最近检测正常，包括 UK；第三方 `Residential@US-LA` 的端到端 HTTP 检测两次失败。它的 TCP 端口可连接（现场约 209ms），检测配置通过 Xray 内核解析；现有证据不能区分上游握手、凭据或出口访问故障。保留真实失败状态，没有伪造耗时、换用共享凭据或更改供应商配置。要继续修复该外部线路，需要核对供应商侧状态或最新连接配置；不能将门户通过测试解释为住宅出口已恢复。
