# 1.2.1 入门教程交互 review

本轮开始时，仓库与 GitHub main 均为 `a1375f3`，线上返回 `1.2.0`。既有 24 项后端检查和生产依赖检查通过。Jetson 门户、检测、计量与 Tunnel 正常，八条线路的源检测、上报和配置同步正常。

| 修改前 | 修改后 | 原因 |
| --- | --- | --- |
| 设备教程之后另有大型“读懂代理”板块 | 把组名解释、图片和详细表格嵌入各设备的选线路步骤，可展开查看 | 将说明放在实际需要做选择的位置 |
| 下载入口是标题旁的小链接 | 安装步骤中的大按钮，标出软件、官方来源和文件用途 | 让首次使用者知道先下载哪个客户端 |
| 长段落顺序阅读 | 四个步骤卡片、固定步骤导航及下一步定位 | 提高扫描和操作的便利性 |
| 教程按钮只打开订阅页，客户端可能仍是以前选项 | Android／Shadowrocket／Stash 等入口先选对应格式再转入订阅 | 修正跨设备引导不一致 |
| 没有验证操作的清单 | 用户自己勾选配置、VPN 和实际访问的检查项，显示已确认数 | 给出检查依据，不自动声称连接成功 |

电脑和 Android 使用相同的 Clash 策略概念；Android 的图片明确标为电脑参考图。iOS 将 Shadowrocket 的节点和应用路由说明，与 Stash 的策略组说明放在各自位置，避免把电脑分流步骤套到 Shadowrocket。共同说明模板只在某设备首次被选择时挂载，图片继续延迟加载。

动画用于回应设备切换和步骤定位：复用已有 160ms Web Animations API 过渡，只改变 opacity／transform，不新增依赖。键盘触发保持即时；减少动态效果时只使用轻淡入。精确指针的按压／悬停沿用原样式。步骤导航和核对计数不表示网站检测到任务完成。

按 ask-sonner 检查后继续使用原有单个 Toaster。教程转入订阅时，只提示所选客户端及应用确认步骤；网站不宣称已经唤起应用或导入成功。

review 还加固了客户端键名校验：本地保存值和导入参数必须是客户端表自身的键，避免原型属性被误当作合法客户端。退出或重新加载账号时清空用户勾选的检查项。

验证包括桌面、390px 深色布局、下载按钮触控尺寸、展开图片、键盘步骤定位、减少动态效果、Android 与 Stash 导入入口的准确选择，以及会话过期后的链接与检查项清理。既有节点、订阅、权限、用量和管理端流程继续通过。截图使用虚构账号。

部署采用新发布目录和停写备份，保留前一版本。上线后检查版本、构建资源、指南内容、现有账号／节点凭据以及检测和上报状态。没有修改节点配置或订阅序列化逻辑，也没有把手机尺寸浏览器结果称为原生 App 导入验证。

最终构建、两套隔离浏览器流程与生产依赖检查通过；移动订阅回归检查在本机和 Jetson 均通过。线上用户与私有管理员健康端点均返回 `1.2.1`，三个发布的指南／控制器／样式文件与本机构建哈希一致。页面已移除独立代理说明面板，四步导航和下载按钮存在。生产账号、节点凭据与源配置与停写备份一致，八条线路的检测、报告和配置同步正常。
