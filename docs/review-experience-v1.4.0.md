# 1.4.0 大屏、测量口径与用户端体验 review

开始时本地／GitHub 为 `1617811`，线上版本 `1.3.0`，工作树干净。原有 33 项后端与四套浏览器流程通过。本轮不更改账号、密码、权限、个人规则、节点凭据或订阅签名，不修改原始私有 YAML，也不调整代理核心或第三方上游。

## 界面 review

| Before | After | Why |
| --- | --- | --- |
| 用户端固定 1660px、管理端固定 1800px，内容靠左 | 侧栏右侧流式内容区，2K 展开、4K 采用居中的 2520px 阅读上限 | 不把剩余宽度全留在右边，也不无限拉长内容 |
| 图表尺寸没有跟随大屏阅读区 | 大屏图表高度按 300–420px 调整，卡片和节点网格响应式重排 | 防止只扩大横向空间而图表比例失衡 |
| 登录与工作台缺少视觉层次 | 本地 SVG 网络轨迹、品牌标记、静态低对比渐变和连接卡片圆弧 | 装饰不表示真实在线状态，不下载外部壁纸 |
| 登录／退出视图突然变化 | 偶发切换使用 160ms opacity／transform；初次登录 200ms、短错峰 | 状态反馈不延迟交互，实时数据和轮询不移动 |
| 键盘和减少动态效果可能受到运动干扰 | 键盘操作立即切换，减动效只淡入，触摸无悬停运动 | 保留可达性和舒适性，复用已有 WAAPI 与曲线，无新动效依赖 |

按 animate／Emil 方案处理“避免突兀变化”和按钮反馈，不做持续旋转、鼠标跟随或图表装饰运动。ask-sonner 保留唯一 Toaster 与准确的加载／失败反馈，不重复弹窗。装饰为代码原生 SVG／CSS，动态值仍是实际账户与计量数据。

## 检测耗时

旧代码计算从启动 curl 到完整退出的时间。现场只读基线得到 348–1328ms 全程，TLS／代理建链占大部分，例如 359ms 的全程含约 272ms 连接准备与 87ms HTTP 响应。换成空响应目标本身并不足以消除这部分耗时。

测量改为 curl 的 [HTTP 首字节与准备时间](https://curl.se/docs/manpage.html)之差，保留连接准备与全程两个数字。优先使用 [Mihomo URL-test 文档同样使用的 Gstatic 204](https://wiki.metacubex.one/en/config/proxy-groups/url-test/)，失败则标明 Cloudflare 回退。现场新方法八个源节点均正常，HTTP 响应约 86–266ms；这证明口径拆分，不宣称物理网络变快或等同客户端 ping。

失败／格式错误／计时顺序异常不生成数字；旧记录明确标为全程口径。附表保存细则、与父记录一起清理，原表不加列，避免破坏旧检查器的插入接口。两端都能查看响应与准备，展开看到全程、目标和观察者。

## 验证边界

大屏布局、键盘即时导航、手机深色界面、减动效与数据刷新复现已通过。未变化刷新移除节点数为零，当前基线平均刷新约 61ms，图表变化更新约 2ms；这些是隔离浏览器的现场测量，不是所有设备的性能承诺。

最终 36 项后端测试在本机 Node 24 与 Jetson Node 22 均通过，五套隔离浏览器流程通过，生产依赖无已知漏洞。场景包括两端 1280／1920／2560／3840 CSS 视口、手机深色、键盘即时切换、减动效、不溢出、两端 80ms 响应与 980ms 准备的独立展示及 1200ms 全程说明。

发布使用停写备份与原子切换，保留前一发布目录。线上用户与私有管理端均为 `1.4.0`，脚本和样式原始 SHA256 与本机一致。账号、配置与设置、个人规则、节点凭据、原有用量与订阅签名均与备份一致。

新检查周期完成后，八条源线路均正常，附表记录了八份新口径，HTTP 响应约 85–266ms，连接准备约 267–728ms，全程仍在 353–964ms；没有声称网络因此提速。门户、检查器、计量、网关与 Tunnel 均 active。后台默认间隔与网页轮询周期未改。

截图使用虚构账号和用量，不发布真实用户图像、订阅或节点密钥。休眠仅针对用户电脑，不关闭 Jetson；操作系统已确认支持休眠，最终动作在推送和验证之后执行。
