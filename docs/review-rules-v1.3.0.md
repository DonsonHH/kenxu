# 1.3.0 规则兼容与个人分配 review

开始时本地与 GitHub main 同为 `d2bdfc4`，线上版本为 `1.2.2`，工作树干净。原有 26 项后端与登录／界面回归通过，五个相关服务处于 active。本轮不重置账号密码，不重发订阅 token，不改动 VPS、UK 会话或第三方上游。

## 复现与修复

完整截图指出 `unsupported rule type: PROCESS-PATH-WILDCARD`。用只包含一个进程路径通配符、一个虚构代理和 MATCH 的配置，在 Mihomo 1.18.10 复现相同错误；1.19.32 可通过。旧解析器的[类型列表](https://github.com/MetaCubeX/mihomo/blob/v1.18.10/rules/parser.go)没有该通配符类型，但支持进程正则。

导出将 PROCESS-PATH-WILDCARD／PROCESS-NAME-WILDCARD 转为锚定的正则，转义路径中的反斜杠、括号和其他元字符，把星号／问号转换成对应匹配，合并重复星号，保留顺序、目标及原始源文件。匹配测试涵盖 Windows 路径、大小写、子目录以及不应命中的其他盘符和目录。旧／新解析器都通过转换后配置。

原源中共 100 条规则，其中七条为进程通配符。对私有源进行了 255 种授权子集的结构检查、八个单节点旧内核校验，以及全节点／单节点的新内核检查。第一次完整内核检查因临时目录缺少地理数据而失败；提供现有资源后通过，不把它当成订阅语法问题。

ASCII 下载文件名改用不带引号的标准 token 写法，避免客户端把引号或转义字符显示成配置名。旧卡片的名称可能已保存，更新规则并不保证自动改名。

## 规则分配

管理端新增全局／用户规则编辑、格式与授权预览、域名规则辅助输入，以及复制当前导出规则到独立草稿。继承跟随全局；补充优先匹配个人列表，再使用全局；独立保存完整列表与自己的兜底，后续全局规则内容修改不影响它。独立方案仍共享节点、策略组定义、DNS 与规则提供器。

规则表单和 YAML 导入共用校验，拒绝未知类型、错误目标、无效网段／常用正则、未知规则集与错误 MATCH 位置。当前简单编辑器明确不支持嵌套 AND／OR／NOT／SUB-RULE 或含逗号的匹配内容。校验不是手机或远程规则集的连通测试。

个人保存不能使用未授权策略；节点授权变化后的订阅也继续过滤授权并拒绝不可达目标。预览不调用凭据分配逻辑，不返回节点凭据，也不保存草稿。修改规则不更改账号、密码、授权、签名密钥和用量；保存后须在客户端更新订阅。

## Review 修正

- 修订号覆盖源内容、个人方案和相关授权，事务内检查，拒绝旧窗口覆盖新状态。
- 规则读取失败时清空旧范围并禁用保存，避免选择用户失败后仍误保存全局内容；重新载入可恢复。
- 用户／角色切换采用请求序列与会话代际检查，旧预览不能覆盖另一个用户，退出清空编辑器和预览。
- ask-sonner 的单 Toaster 继续复用，规则操作用同一个 promise 通知标识；准确区分预览通过、草稿未保存、保存成功与失败。
- YAML 导入也进行规则校验，避免绕过编辑器；审计仅保存方案与数量，不含规则全文。
- 自定义表外键随账号删除清理，默认所有现有用户继续继承，不部署示例规则到真实账号。
- 登记中的受管直连节点曾允许未登记用户回落到共享源凭据；改为与中转一致，完成个人登记后才广告／分发该节点。旧试点测试的共享回退预期随之改为拒绝，新增回归覆盖这一缺口。线上核对缺口数量为零，不需要重配现有节点凭据。

## 验证边界

最终 33 项后端测试在本机 Node 24 和 Jetson Node 22 均通过，四套隔离浏览器流程通过，生产依赖检查无已知漏洞。新增流程覆盖规则保存、独立草稿、失败读取恢复、迟到预览隔离、公开用户权限、退出清理和 390px 深色布局。截图使用虚构账号和域名。

发布采用停写备份与原子切换，保留前一发布目录和完整私有数据。用户端与私有管理端健康接口均返回 `1.3.0`，公开脚本／样式的原始 SHA256 与测试构建相同。门户、检测、采集、网关、Tunnel 均 active；八条逻辑线路均有近期报告与正常源检测。

对比停写备份，账号、密码、权限、节点凭据、源配置与设置、已有流量记录以及订阅签名密钥保持一致，新增个人方案表为空。通过回环 HTTP 对三个已激活账号的实际订阅进行只读检查：全部返回 `200`，进程通配符已转换，授权节点和独立 UUID 正确，未生成额外凭据。未替真实用户创建测试规则。

朋友的具体内核版本未知，真实设备更新订阅后的结果仍需本人确认；原生 Stash／Shadowrocket 未重新现场验证。解析器检查不等同于终端连通验证。
