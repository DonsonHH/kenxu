# 1.4.2 失效住宅线路退役 review

起点：本地工作区干净，GitHub main 与本地为 `45907fc`，线上 1.4.1。原 37 项后端测试与五套隔离浏览器流程通过。用户确认住宅美国出口失效，并授权同步清理原始 YAML。

## 已审查与修正

住宅和日本备用出口共享 Jetson 采集器，住宅线路的计量行是最初的物理采集登记。直接停用该行会使原采集令牌失效，连带阻断日本线路的配置同步和计量上报。现在逻辑退役与物理采集身份分别处理：只要仍有启用的共享线路，原令牌继续服务它们；退役线路不进入配置或采集期望状态，没有启用的线路后令牌失效。

私有 `retire-node` 命令事务化移除源节点、策略组成员和用户授权，保留账号、会话、订阅链接、其余节点凭据及历史用量。遇到直接规则引用、前置节点依赖、空组或最后一个节点时拒绝猜测替代策略。现场住宅节点只被两个策略组引用，没有全局／个人规则直接引用。

原始 YAML 的操作先创建备份，再复用同一规则安全清理。重读验证七个剩余节点和所有非目标分流设置与备份一致，不将私有源或备份提交到 GitHub。

## 回归

新增测试涵盖共享采集锚点退役、旧队列与历史计数保留、账号／订阅签名不变、其他节点 UUID 保留、歧义操作拒绝、原始 YAML 注释与字段保留，以及同一订阅 URL 的 Clash／Stash／Shadowrocket 输出不包含退役节点。只有退役节点权限的账号不会被自动授予其他节点。

本机 41 项后端测试通过，生产依赖审计无已知漏洞。最终浏览器与 Jetson 发布验证在现场完成后记录；不能把测试通过或服务重启等同于实际客户已刷新缓存。

## 发布确认

Jetson Node 22 的 41 项测试和五套隔离 Edge 浏览器流程均通过。线上两端为 1.4.2，门户、检测器、采集器、中转与 Tunnel 均 active；关键源码 SHA256 与本机一致。未变化列表在刷新测试中移除节点数为零，平均刷新约 67ms、变化图表更新约 2.1ms，仅为当前隔离环境测量。

生产源由八个节点减少至七个，四个账号移除了住宅权限，其他授权、账号密码、订阅版本、个人规则、非源设置、节点 UUID、历史用量与签名密钥通过备份对照。数据库完整性为 ok，外键违规为零。三个已完成首次改密的有效账号，使用原订阅链接检查了九份 Clash／Stash／Shadowrocket 输出，均已去除住宅节点；尚未改密的账号在完成原有首次改密流程后也使用同一已清理配置源。

中转热同步确认退役客户端已删除，日本线路的三个现有客户端及原凭据与期望状态一致。只移除了无剩余路由引用的住宅上游出站，持久配置通过 Xray 校验并得到运行时删除确认，共用代理核心 PID 未变。采用的是 Xray 官方 [RemoveOutbound 接口](https://github.com/XTLS/Xray-core/blob/main/main/commands/all/api/outbounds_remove.go)，不是通过重启整个中转清除线路。

原始 `Donson.yaml` 已清理，备份位于同目录的 `Donson.yaml.before-residential-removal-20261008.bak`，仅移除目标节点及两个策略组中的成员引用。服务端完整私有数据和中转配置另有停写备份，上一发布目录保留。私有凭据扫描无跟踪文件匹配，不将真实账号、配置、备份或令牌推送到 GitHub。

## 客户端更新边界

服务端发布后，所有既有订阅链接返回清理后的配置，不要求重新分发链接。网站不能直接改写用户手机或电脑的已下载文件；客户端按其自动更新设置拉取，原 720 分钟建议不变。立即生效可手动更新订阅，本地文件用户重新下载／导入。
