# 1.2.2 首次登录与入口安全 review

本轮开始时，本地与 GitHub main 同为 `6dd5816`，线上版本为 `1.2.1`。原有两套隔离浏览器流程可完成首次登录、强制改密与再次登录；新建账号中有一个已完成改密，两个仍未完成改密。未发现这两个账号被停用、到期或命中账号级认证限流。

## 发现与修复

用户报告点击登录就出现“请求来源不匹配／操作验证失败”，尚未进入改密页。代码中来源检查发生在密码校验之前，登录接口没有已登录操作的 CSRF 检查；不能把这个报错当成初始密码错误。

实际 HTTP 探测发现公开域名的 HTTP 根页面返回 `200`，没有 HTTPS 跳转，而接口要求准确的 HTTPS Origin。这使 HTTP 入口可以显示登录页，却不能完成登录，也是首次访问时的安全缺口。`test/canonical-origin.test.mjs` 在旧代码返回 `200` 时失败，修复后返回 `308` 并通过。未获得用户当时的网络记录，因此这一缺口是已复现的问题，不声称已确认他那次请求的具体协议。

另一个兼容性问题通过真实浏览器请求复现：旧的全局 `no-referrer` 策略，在 Firefox／WebKit 的同源 fetch 模式下产生 `Origin: null`，导致相同的 `403`；Edge 在相同测试中没有失败。这与 [Fetch 规范的 Origin 生成规则](https://fetch.spec.whatwg.org/#append-a-request-origin-header)有关，不是允许空来源的理由。

修复保留准确 Origin 与 CSRF 校验：

- 仅在明确配置的公开 HTTPS Tunnel 入口、且请求来自回环地址时，读取 [Cloudflare 的访客协议头](https://developers.cloudflare.com/fundamentals/reference/http-headers/#x-forwarded-proto)。普通 HTTP GET／HEAD 导向配置中的 HTTPS origin，不使用请求 Host 拼出目的地。
- 不重定向密码提交、Bearer 请求或订阅／配置下载，避免自动重放敏感请求。未经过 Tunnel 的本机健康检查不受影响。
- 操作页面改用 `same-origin` 引用策略，API fetch 明确使用同源模式和策略；订阅／配置路径，包括大小写和尾斜杠别名，继续使用 `no-referrer` 与 `no-store`。
- 外站、缺失／`null` Origin、错误 CSRF 继续拒绝，不扩大 CORS、不以 Referer 替代来源、不绕过认证限流。

## 账号与错误提示

原初始密码交付文件已不含账号密码记录，不能从数据库的 scrypt 散列还原旧密码。按用户本轮明确要求，只重发尚未完成首次改密的两个新账号，不触碰已激活账号。重发前要求账号仍是启用的普通用户、仍需首次改密、没有有效会话，并在事务内再次核验状态。

重发保留账号标识、权限、用量、节点独立凭据和强制改密状态；不会替用户完成首次改密。初始密码文件只在私有目录交付，不加入仓库。线上验证需要登录到改密页后退出，真实账号的新密码仍由用户自己设置。

按 ask-sonner 检查现有单个、跟随主题的 Toaster，错误提示保留准确原因和刷新建议，不把认证失败包装成成功或制造重复通知。桌面入口检查确认使用 `http://127.0.0.1:4451`，不改动管理员密码或扩大管理端暴露。

## 验证边界

最终 26 项后端测试在本机 Node 24 和 Jetson Node 22 均通过；原有两套 Edge 完整页面流程与新增来源／CSRF 流程通过，Firefox 与 WebKit 的两种 fetch 模式也通过。生产依赖检查无已知漏洞。没有遗留临时调试日志。

发布使用停写备份与原子切换，保留前一发布目录和完整私有数据备份。线上用户端与私有管理端均返回 `1.2.2`；HTTP 根页面从 `200` 改为 `308`，隔离 Edge 实际导航为 HTTP `308` → HTTPS `200`。公开脚本与服务器文件的原始 SHA256 一致，按 LF 规范化后也与已测试并暂存的 Git 内容一致。

重发后的两个账号分别通过线上真实页面登录，`/api/login` 和后续 `/api/me` 返回 `200`，显示强制首次改密页，无页面异常，随后正常退出；没有代替他们设置个人新密码。文件传输 SHA256 一致，本机密码文件限制为当前用户与 SYSTEM 可访问，并清理服务器上的临时明文交付副本。密码文件与私有辅助脚本不进入 Git。

发布后与停写备份对比：其他账号、两位待改密用户的其他资料、节点凭据与授权、源配置和设置、原有流量记录及订阅签名密钥均保持不变。门户、检测、计量、网关和 Tunnel 服务都处于 active；八条逻辑线路均有近期上报与正常源检测。

三种引擎验证不等同于用户原浏览器或手机原生客户端实测。本轮不修改 VPS 核心、UK 会话、第三方上游配置或原始私有 YAML。
